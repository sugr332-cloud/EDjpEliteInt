# キー入力先の保護と FSD 表記（H-1 / J-19）

**Status:** Draft（2026-09-27）
**正本との関係:** `docs/ELITEINTEL_INTEGRATION_PLAN.md` §R.13 の統制手順に従う。

## 0. 背景（2026-09-27 実機）

- AI タブの入力欄に「マップ開いて」と打つと、ゲームのギャラクシーマップは開かず、アプリのチャット欄に「+」が入った。「ジャンプしろ」も、ジャンプ先と「FTLの準備中です」が表示されただけで、ゲームは動かなかった。
- 原因: キー入力は Windows の **前面のウィンドウ** に送られる（`WindowsNativeKeyInput`）。文字入力ではアプリが前面なので、ゲーム用のキー（ギャラクシーマップのキーなど）がアプリ自身の入力欄に入る。ゲームを前面に出す処理（`GameWindowActivator`）は GUI ボタン経由（`GuiCommandRunner`）でしか呼ばれていない。音声入力はゲームが前面のまま話すので、この問題が表に出なかった。
- 危険性: 前面がアプリ以外（ブラウザ・チャットツール等）の場合、ゲーム用のキーがそのアプリに打ち込まれる。
- 日本語の表記: `responses_ja` / `gui_ja` が英語版の「FTL」をそのまま使っている。Elite Dangerous の日本語話者の用語では、船の超光速航法は FSD（フレームシフトドライブ）で、スーパークルーズとハイパースペースジャンプの両方を FSD が行う。

## 1. H-1: ゲームのウィンドウを覚えておき、コマンド実行の直前に手前に出す

**ウィンドウの把握（先に見つけて覚えておく）**
- アプリ起動時に Elite Dangerous のウィンドウを 1 回探し、その識別子（HWND）を覚えておく
- コマンドのたびには探さない。覚えている識別子が無効（ゲーム終了・再起動でウィンドウが消えた）と分かったときだけ探し直す
- 探し方は既存 `GameWindowActivator` と同じ（タイトルに "elite - dangerous" / "elite dangerous" を含む表示中のウィンドウ）。この処理を共通部品として使えるようにし、`GuiCommandRunner` の動作は変えない

**手前に出すタイミング（1 コマンドにつき 1 回）**
- ゲームにキーを送るコマンド（ギャラクシーマップを開く、ジャンプ等）の実行を始める直前に、1 回だけ行う。1 つのコマンドの中で複数回キーを送っても、確認・前面化は最初の 1 回だけ
- キーを送らないもの（質問・会話・検索だけの Query 等）では何もしない（アプリの画面に出た答えが隠れないように）
- 手順:
  1. 前面ウィンドウが覚えているゲームのウィンドウなら、何もしない（声で話したときの通常経路）
  2. そうでなければ前面にする。前面になったことを最大 2 秒まで確認し、その後、短い待ち（定数、初期値 300 ms）を置いてからコマンドを実行する
  3. ゲームのウィンドウが見つからない、または前面にできなかったときは **そのコマンドのキーを送らない**。「ゲームのウィンドウを前面にできないため、操作を送りませんでした。」を読み上げる（EN も用意）。ほかのアプリにキーが入ることを防ぐ
- 保険: キーを実際に送る共通の入口でも、前面がゲームでなければ送らない（上の手順を通らない経路があっても、ほかのアプリにキーが入らないようにする）。ここでは前面化はせず、送らずにログを残すだけ
- Windows 以外（Linux 等）は現状どおり（判定をしない）

**既知の制約**
- ゲームが前面に来たときに音声デバイスがリセットされ、直前に始まった読み上げが途切れることがある（`GuiCommandRunner` が 3 秒待つ理由）。H-1 の待ちは 300 ms とし、途切れが実機で問題になれば別途調整する

**テスト**
- ウィンドウの検索・前面判定・前面化・待ちを差し替え可能にし、次を検証する（実機のウィンドウ操作・キー送信はしない）:
  - (a) 覚えているウィンドウが既に前面なら前面化しない
  - (b) 前面でなければ前面化してから実行する
  - (c) 1 コマンドで複数回キーを送っても前面化は 1 回
  - (d) 見つからない・前面化失敗なら送らず中止メッセージ
  - (e) 識別子が無効になったら探し直す
  - (f) キーを送らないコマンドでは何もしない
  - (g) 保険の入口で前面がゲームでなければ送らない

## 2. J-19: 日本語の「FTL」を「FSD」に

- `responses_ja.properties`: `handler.fsd.nodestination`、`handler.supercruise.massLocked`、`handler.supercruise.preparingFtl` の「FTL」を「FSD」に（例「FSDの準備中です。」「マスロック状態のため、FSDは使用できません。」「FSDの目的地が設定されていません。」）
- `gui_ja.properties`: `automation.*ForFtl` の 5 キーの「FTL移行時に」を「FSD起動時に」に
- キー名・英語版は変更しない。`ai_action_aliases_ja.properties` の「FTLをドロップ」は言い回しとして残してよい
